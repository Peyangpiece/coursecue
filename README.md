# saboro

授業・課題・提出状況・本人対応タスクを管理するアプリ。

未接続でも授業・課題・締切・下書き・提出済み記録を利用できる。データはブラウザ内に保存し、設定からJSONバックアップを出力・読込できる。ブラウザの保存データを削除すると消えるため、バックアップを利用する。

manabo自動連携は、各自の Mac に入れたサービスと接続キーで動く。クラウド（Worker + D1）は利用者ごとに分かれていて、Mac のセットアップが作った接続キーと Mac の鍵（それぞれ 64 桁の乱数）の SHA-256 だけを `accounts` に登録し、状態（`account_state`）と処理の待ち行列（`account_jobs`）はその利用者だけが読み書きできる。最初の利用者は環境変数の旧トークンでそのまま使える（`legacy`）。登録（`/api/register`）は認証なしなので 1 時間に 20 件まで。

## 構成
- 公開UI: Cloudflare Workers（`dist/_headers` の CSP で、スクリプトは自分のものだけ・画像と接続は自分と PC 内のサービスだけ）。Firebase Hosting は旧 URL の転送だけ
- 認証付き同期API・処理キュー: Cloudflare Worker + D1
- Macエージェント: `local/bridge.js`（15秒ごとにキュー確認、毎日16:30に同期。授業の開始時刻になったらその授業だけ同期）
- 学年暦: 管理者画面の「学年暦」で更新する。期間の終わりの 30 日前から「要更新」と運営通知が出るので、大学の新しい学年暦（PDF）の URL を入れて読み取り、中身を確かめて保存する（AI で読み取る。`server/calendar.js`）。保存したものを `/api/academic-calendar` で配り、PC は今の学年暦の期間が終わった後の同期で 1 日 1 回まで確かめて取り込む（配布し直さなくてよい）。保存したものがなければ同梱の `dist/academic-calendar.json`。シラバスは学期の最初の同期でだけ読み、同じ学期の間は保存したテキストを使う
- manabo操作: Playwrightの専用ブラウザ。大学の正規のログインフォームを利用
- 課題生成: 資料テキストを根拠に構造化出力で生成。本文（draft・記述式の回答）はそのまま提出できる文章だけにし、見出し記号・強調・箇条書き記号・引用符などの記号や Markdown、本人への指示・助言は入れない（生成後にも取り除く）。確認が必要な点・一般知識で推定した旨は notes に分け、課題詳細の「注意点」に表示する。本文は大学生が自分で考えて書いたように見える自然な文章にする（`local/generate.js` の `WRITING_RULE`：段落ごとに一つの話題、設問の言い直しや「本レポートでは」で始めない、「以上のことから」などの中身のない総括で終えない、反対の見方や例外に一度は触れる、「〜することが重要である」「様々な」「〜において」などの AI らしい定型・硬い言い回しや「まず・次に・最後に」の並べ方を避ける、文末と文の長さに変化をつける、考えが動いた過程や言い切らない部分を入れる、書き終えたら読み返して直す）。利用者どうしの回答が似ないように、書き出し・流れ・例の使い方・文の形・締めくくり方を利用者ごと・課題ごとに変える（`writingStyle`。同じ人・同じ課題なら同じ）。本人の過去のレポートから読み取った文体（設定の「文体」）があればそれに合わせる。本文に「です・ます」や AI らしい言い回し（総括の決まり文句、「本レポートでは」、「〜ことが重要である」の繰り返し、「まず・次に・最後に」の並べ方など）が残っていれば注意点で知らせる（意味が変わりうるので自動では書き換えない）。Codex CLI → Claude Code（`claude -p`）→ SaBoRo の AI（こちらの API キーでクラウドが作る。`claude-sonnet-5-5`）の順に試し、未インストール・未ログイン・利用枠超過・形式不正などで失敗したら次へ進む。どの手段で作ったかは画面に出さない
  - SaBoRo課題サポート：使えるのは定期支払いが有効な人と、管理画面で登録した利用者（停止中を除く）だけ（アカウントは誰でも作れるため）。月の課題生成 60 回までは月額に含み、それを超えた分は使用量（実費×1.5 倍）を月額と一緒に請求する（毎日の集計で請求項目にし、請求済みにするのは集計した行だけ。集計のあとに記録された分は翌日に回す）。急がない回答は Batch（半額。通常 1 時間以内、最大 24 時間）で作り、出来上がったら自動で入力する（`server/ai.js`）
  - 高度な生成：高性能なモデル（Opus 5.5、`ADVANCED_MODEL`）で出力の上限を 64000 トークンに広げて作る。課題の詳細に出すのは、Word・PDF などのファイルで提出する課題、期末・中間レポートなどの名前の課題、字数の指定が 1000 字以上の課題（`dist/task-rules.js` の `advancedEligible`。画面とアプリで共有）と、出力が上限（32000 トークン）で途切れた課題（自動では作り直さず本人の対応待ちにする）。月 3 回まで月額に含み（サーバーで原子的に数える）、4 回目以降は超過分として請求できる人だけ実費×1.5 で使える（`record` の billable）。同じ内容で作った回答があっても高度な生成は作り直す
  - 費用の上限：月額に含む分で使える実費は 1 人・月 15 ドルまで（管理画面で変更。授業情報の読み取りも数える。無料分を超えて請求できる人でも、請求しない処理（質問の作成・文体の読み取り・会話の読み取り）はこの上限で止める）、1 回の依頼は資料込み 30 万文字・出力 32000 トークンまで、同時に作るのは 5 件まで・1 日 200 回まで、月の無料分の回数（請求できない人）と高度な生成の回数も、作る前の予約の 1 文で原子的に数える（`ai_inflight`）
  - 急ぐもの（本人が画面で頼んだ・提出の操作・締切まで 24 時間以内・初回の同期）はすぐ作る。同じ依頼の Batch があれば二重に作らず、出来上がっていればその結果を使い、まだなら Batch を取り消してからすぐ作る。授業情報の読み取り（教室・授業形式・欠席上限など）も同じで、初めて読む授業・初回の同期・次の授業が明日までの授業はすぐ、それ以外は Batch。一度読んだ資料は読み直さず、第1回までの資料・シラバス・お知らせが変わったときだけ全体を、第2回以降はまだ読んでいない資料の抜き出しだけを渡す（`local/timetable.js` の `courseInfoPlan`）
  - CLIの場所は自動で探す。見つからない場合は `COURSECUE_CODEX` / `COURSECUE_CLAUDE` で指定。モデルは `COURSECUE_CLAUDE_MODEL`（Claude Code）で変更可
- 認証情報・接続キー: macOSキーチェーン。平文パスワードはクラウドへ送信しない。公開設定はRSA-OAEP + AES-GCMで暗号化し、登録Macだけが復号する。ただし画面は復号用の公開鍵を Worker から受け取るので、この保証は「Worker（クラウド）を運営者が正しく動かしている」ことが前提（Worker が差し替えられれば、送られる暗号文は読める。クラウドのログや保存先から平文が漏れないための仕組みであって、運営者を信頼しなくてよい仕組みではない）。manabo のページ本文・シラバス・お知らせ・課題の説明は、学籍番号などの ID（英字＋6 桁以上の数字）を除いてからクラウドへ送る（`local/core.js` の `scrubIds`）

## セットアップ（デスクトップアプリ：Mac・Windows）
GitHub の Release（https://github.com/Peyangpiece/SaBoRo/releases/latest ）から自分の OS 用を入れる（Mac は `.dmg`、Windows は `.exe`）。起動すると常駐し（メニューバー／タスクトレイ）、ログイン時に自動で立ち上がる。初回は manabo 用のブラウザ（Chromium）を取り込む（数分）。その後に開く「はじめの設定」で済ませるのは 3 つだけ：
1. manabo のログイン ID とパスワードを保存する（このパソコンの中だけに暗号化して保存。Mac はキーチェーン、Windows は DPAPI。保存と同時に manabo への接続を確認）
2. SaBoRo課題サポートを確認する（設定は要らない。「使えます」と出ればよい）
3. 「saboroを接続」でアプリ内の画面を saboro に接続する

スマホでも使える（PWA）。メニューバー／タスクトレイの「スマホと連携（QR コード）」（設定画面の「4. スマホと連携」）に出る QR コードをスマホのカメラで読むと、同じ接続キーで saboro の画面が開く（接続の確認で「接続する」を押す）。iPhone は Safari の共有メニュー、Android は Chrome のメニューの「ホーム画面に追加」でアプリのように開ける（`dist/manifest.webmanifest`、`apple-mobile-web-app-capable`）。スマホからは課題・締切・時間割・お知らせの確認、同期の指示、出席コードの入力ができる。manabo を自分で操作するための直接リンク（状態の欄の「manabo を開く」、授業ページ・時間割の回・今日の授業の「manabo で開く」（授業 ID が分かる授業はその授業ページ）、出席コードの案内の「manabo で自分で入れる」）を出す。manabo の自動操作（同期・ダウンロード・回答の作成）はパソコンのアプリが行うので、パソコンが起動している必要がある。QR コード（`/qr.svg`）には接続キーが入っているので他の人に見せない（PC のサービスの中だけで出し、ほかのサイトのページからは読めない）。iPhone の「ホーム画面に追加」した saboro は Safari と保存場所が別で接続キーを持たないため、接続している画面はマニフェストを `/api/manifest?connect=<接続キー>`（`start_url` に `?connect=` を入れて返す。認証なし。Workers の要求ごとの自動の記録は切ってある）に差し替え、追加した saboro を初めて開いたときに「接続する」で同じ接続先につなぐ。つながっていないときは、未接続の画面の「QR コードを読み取って接続」でその画面のカメラからパソコンの QR コードを読む（同梱の jsQR `dist/jsqr.js`。使うときだけ読み込む。カメラを使えなければ撮った写真から読む）か、接続済みの saboro の設定 → manabo連携 の「接続用リンクをコピー」で写したリンクを「接続用リンクを貼り付けて接続する」に貼る。App Store／Google Play には出していない（Apple Developer Program が必要なため）

授業の一覧・授業日・課題・締切・資料は接続後の同期で manabo から自動で集める。資料はデスクトップの「<西暦>_<学期名>」（例：`2026_秋学期`）の中の「<授業名>/」に保存する（学期が変わると新しいフォルダ）。アプリは Release の最新版を自動で確認して更新する（Mac は署名がないため自動更新が効かず、新しい版を入れ直す。新しい版を見つけたら案内の画面とメニューバーの「新しい版をダウンロード」で知らせ、押すとアプリが自分の CPU 用の .dmg を「ダウンロード」フォルダに落とし、終了してから小さなシェルスクリプトが「アプリケーション」の saboro を入れ替えて開き直す（`desktop/mac-update.js`。落とした .dmg は Release の版の情報（latest-mac.yml）の sha512 と照らし、合わないものは使わない（「ダウンロード」フォルダに同じ名前のものがあっても同じ）。入れ替えるスクリプトは .dmg を自分の作業用フォルダに写してから sha512 をもう一度確かめ、同じ CFBundleIdentifier の saboro だけを取り出し、版と署名（壊れていないこと。いまの saboro が証明書で署名されていれば同じ証明書であること）を確かめてから入れ替える。失敗したら元の saboro のまま開き直して手動の手順を案内。書き込めない場所で動いているときは .dmg を開いて案内。落とせなければダウンロードのページを案内）。Apple Developer の署名を CI の `CSC_LINK` に設定すれば自動更新が有効になる）。配布物は Apple の署名がない（Mac は、GitHub の Secrets に自分で作ったコード署名の証明書 `MAC_SIGN_P12`・`MAC_SIGN_PASSWORD` があればそれで、なければ ad-hoc で署名する（`desktop/after-pack.cjs`）。同じ証明書で署名し続けると、キーチェーンの「常に許可」が更新のあとも引き継がれる）ので、Mac では初回に開こうとして止められたあと「システム設定 → プライバシーとセキュリティ」の「このまま開く」、Windows では SmartScreen の「詳細情報 → 実行」が必要
- アプリの作り：`desktop/main.js`（Electron）。画面は saboro 本体（クラウド）と PC 内のサービス以外へは移動せず、ほかのサイトへのリンク・転送は既定のブラウザで開く。OS 固有の処理（秘密の保存・ファイルを開く・ゴミ箱・フォルダ選択・再起動）は `local/platform.js` の組を `globalThis.saboroPlatform` で差し替える。アプリ本体は `local/bridge.js` をそのまま動かし、`COURSECUE_DESKTOP`（デスクトップの場所。資料の既定の置き場所はこの中）・`COURSECUE_WORK`（作業場所）・`PLAYWRIGHT_BROWSERS_PATH` を渡す。git による自動更新はアプリでは無効
- 配布物の作成：`.github/workflows/desktop.yml`（タグ `desktop-v*` または手動）で macOS・Windows のインストーラーを作り Release に載せる。「最新版」の印は公開済みのどのバージョンより新しいときだけ付ける。公開（`deploy.yml`）は `package.json` のバージョンを Worker の `APP_VERSION` として渡し、画面はつないでいるアプリがそれより古ければ「新しいバージョン x があります」と更新を案内する（1 つのジョブで両方を作り、下書きの Release に載せてから gh で公開する。版は `package.json` の `version`。同じ版の作りかけが残っていれば消してから作る）。手元では `npm run desktop`（起動）／`npm run desktop:build`

### コマンドラインでの導入（Mac、開発者向け）
```
curl -fsSL https://coursecue.hrk-6888.workers.dev/install.sh | bash
```
`~/saboro/app` にアプリを置き、Node.js 22・manabo 用ブラウザ・Mac サービス（launchd）を入れて、同じ設定画面（http://127.0.0.1:8766/setup ）を開く。`npm run setup` は利用者の登録（接続キーと Mac の鍵を作ってクラウドに登録）・ブラウザの用意・Mac サービスの登録を行う。手元で開発するときは `npm ci` のあと `npm run setup -- --no-agent` と `npm start`。既存の課題フォルダの記録を取り込むには `npm run seed`（最初の利用者向け）。Windows でコマンドラインから動かすときは秘密を DPAPI で暗号化したファイルに保存し、ごみ箱・フォルダ選択は PowerShell で行う

## 実装範囲・提出制御
- 新しい課題の検出は実行日の前後7日の授業回が対象。授業タイトルの日付、設定済み日程、または大学の学年暦（`dist/academic-calendar.json`、2026秋学期）を使う。学年暦は授業ページの「（金曜／2限）」表記から曜日を読み、祝日・休講日を除いた第1〜15回の日付を未設定の回に入れる
- **資料の自動ダウンロード**：同期のとき、まだダウンロードしていない資料だけを授業ごとのフォルダ（なければ作成）に保存する。保存先は画面の「設定 → 自動処理 → 資料のダウンロード先」の「フォルダを選択…」で、Mac に出る「フォルダを選択」画面から選ぶ（ホームフォルダ内のみ。既定はデスクトップの「<西暦>_<学期名>」フォルダ（学年暦の学期から。例：`2026_秋学期`。コマンドラインでは `COURSECUE_ROOT` で固定できる）。「既定に戻す」でそこに戻る。保存先を選んでいない人は、以前の既定（「書類/saboro」など）に保存した記録があれば、起動時にその場所を保存先として引き継ぐ（`adoptMaterialsRoot`。同じ資料をもう一度落とさない。一度だけ）。授業ページの「お知らせ」に付いているファイルも、その授業のフォルダに保存する（manabo のお知らせ欄 `#div-class-news` は AJAX で入り、[+] の見出しだけが出ていて本文は押すと入る。読む前に、欄の中で jQuery のクリック処理（要素に直接付いたもの・document に委譲されたもの）・onclick・# のリンク・[+] の画像などが付いた要素を一度ずつ押して開く。`local/manabo.js` の `openNotices`）。そのフォルダで初めての同期のときだけ、対象期間外の回も含めて全回の資料を確かめる。自分で消した資料や、編集して内容が変わった資料は（同じ URL の記録があれば）ダウンロードし直さない。授業ごとに保存するファイルの種類（PDF・Word・Excel・PowerPoint・画像・動画・音声・その他。拡張子で決める）を授業の設定の「保存するファイルの種類」で選べる（既定はすべて。授業の情報に「保存する資料」として表示。`local/download-dir.js` の `FILE_TYPES`）。外した種類は次の同期から保存せず（授業フォルダも作らない）、課題の作成・授業情報の読み取りにも使わない。資料名に拡張子がなければ一度取りに行ってファイル名で決め、保存しなかった URL は `skippedFiles` に覚えて次からは取りに行かない（Mac/PC の中だけ。クラウドへは送らない）。種類を足せば次の同期で保存する。保存済みのファイルは消さない。同じ資料の「4up」「2up」「4in1」「2分割」「4分割（バージョン）」などの印刷形式違いがあるときは 1up（印なし・「分割なし」）だけを保存する（1up がない組はそのまま）。以前に保存した 2up・4up は、同じ授業に 1up があり本人が編集していなければ Mac のゴミ箱へ移す
- **資料を開く**：授業ページの「資料」で資料名を押すと、Mac に保存したファイルを Mac の既定のアプリで開く（Mac サービスの `http://127.0.0.1:8766/open?id=<sha256>` 経由。記録済みでダウンロード先の中にある書類・画像・音声・動画だけ。実行できるファイルや書庫は開かず、manabo のリンクから開く。ダウンロードしたファイルには OS の「インターネットから来たもの」の印（Mac は検疫属性、Windows は Zone.Identifier）を付け、開くときに OS が確かめる）。Mac サービス（127.0.0.1:8766）は、Host が違う要求・別のオリジンからの POST・別のサイトのページからの GET（`Sec-Fetch-Site: cross-site`）を断る（`local/local-server.js`。画面から使う `/open`・`/owned`・`/ping` は除く）。Mac 以外の端末ではローカルサーバーに届かないため、manabo 上のファイルを開くリンクを主にし、「Mac」は補助にする
- **複製の整理**：以前の同期で「名前 (2).pdf」として保存してしまった複製は、Mac サービスの起動時と同期のたびに Mac のゴミ箱（`~/.Trash`）へ移す。対象は、記録と同じ中身（本人が編集していない）で、元の名前のファイルが残っているものだけ。元のファイルや編集した複製には触れない。移した件数と名前はホームに表示する
- **同期の速さ**：全授業を回って提出状況・資料を集め、保存して画面に反映してから回答を生成する。授業ページは 3 件ずつ並行して回る（`COURSECUE_SYNC_PARALLEL` で 1〜5 に変更可）。同期中は画像・フォント・動画を読み込まない。未提出課題の提出確認は授業ページを開いたついでに行う。CUBICS は直近 1 時間に読んでいれば省く。別タブで開くシラバスは 7 日に一度だけ読み、間は `tmp/coursecue/syllabus/` に保存した本文を使う（お知らせは毎回読む）。PDF などの本文の読み取り結果は `tmp/coursecue/text-cache/` に置き、ファイルが変わらない間は読み直さない。クラウドへの送信は授業ごとにまとめる。ホームに前回の同期にかかった時間（CUBICS・授業・回答生成の内訳）を表示する
- 登録済みで未提出の課題は、対象期間や授業日の設定に関係なく毎回の同期で提出状況を確認する。取り込んだ課題（`npm run seed`）は、同じ回の課題のうち題名が一致するもの、なければ種類（レポート・クイズ・掲示板）が同じ唯一のものに対応づけ、締切も入れる。特定できないときは候補を残し、課題詳細の「manabo の課題と対応づける」で本人が選ぶ
- 締切は manabo の「期間」「受講期間」から読む。一覧の行に期間がないときだけ、リンクの次の行（リンクのない行）も見る（まだ開いていない別枠の行や次の回の行は足さない）。それでも読めない未提出の課題は、課題のページ自体を開いて「期間」「期限」の行から読む（課題詳細には「課題ページ：…」として表示）。全角の数字・コロン、「〜」「−」などの範囲記号、「2026/10/20 00:00」の形も読む。開いた回の一覧は `tmp/coursecue/class/<授業ID>_<回>.html` に残す（読めないときの確認用）。manabo に期間がない課題は、資料の本文の「提出期限」「締切」「まで」の行（なければ生成時の注意点）から読む。「10月19日24時」は 10月20日 0:00 として扱う。読んだ出どころ（manabo の表示・課題ページ・資料・注意点）は課題詳細の締切の下に表示する。提出を止めた理由（引用の不一致・締切超過など）は要対応の文言に出す。引用と資料本文の照合は空白・全角半角の違いを無視する（PowerPoint の本文は単語の間に空白が入ることがある）「～ 10月13日(火) 00:00」のような範囲の終わりを締切にし、「10月13日(火) 00:00 ～」のような開始だけの表示は締切にしない。回番号は「第3回」「第３回」「第三回」「第3講」「3回目」のどれでも読む。「期限後提出用」「やむを得ない事情のみ」などの別枠は、通常の提出先がある回では無視する（課題にしない・候補に出さない・締切を読まない）。以前の同期で別枠に結びついていた課題は、同じ種類の通常の提出先が 1 つだけなら、そちらへ付け替えて締切を入れ直す
- 一覧の提出済みチェックは提出済み。下書きと提出済みを区別
- 新規課題は資料から生成。根拠引用が資料と一致しない場合は自動提出しない
- 本人の経験が足りない場合は要対応。補足入力後に生成できる
- クイズは「回答開始」から設問ページへ進み、資料を根拠に自動入力する。回答入力後は専用ブラウザを保持して停止し、本人がmanaboの提出ボタンを押す。アプリが manabo の提出ボタンを押すのは、出席コードのある回で本人がアプリの「出席コードを入れて提出」を押したときだけ。それ以外の自動提出・代理提出は行わない
- 出席コードがある場合は問題だけ回答し、ブラウザをそのまま残して待機。同期も一時停止
- **授業ページの出席コードの入力**：同期中に授業ページで出席コードの入力（manabo の `prompt`）が出たら、そのタブは入力が出たまま残し、残りの授業は別のタブで読み進める。同じ入力（manabo の文言そのまま・入力欄・OK）を SaBoRo の画面にも出す（ホームにも「入力する」）。画面で入れたコードは PC が manabo の入力に渡し（クラウドの仕事 `prompt`）、もう一度求められなければタブを閉じてその授業だけ読み直す。違うコードでもう一度求められたら画面にまた出す。manabo ブラウザで直接入れてもよい（`local/manabo.js` の `answerPrompt`、`state.prompts`）
- 通常レポートは自動生成まで。アプリの「提出」を本人が押した場合だけ送信
- 試験形式は対象にしない。クイズの自動提出の設定はない（上記の出席コードの提出だけ）
- 送信直前に意図をローカル記録し、結果不明は再送しない
- 追加認証・未知のフォーム・単独で特定できない提出ボタンは本人対応
- 実データは接続キー必須のAPI内だけに保存。未認証で参照できない
- Macが起動・ログイン中のみ動作。クライアントだけではmanaboを操作しない

## 自動修正・自動公開（GitHub）
- **修正:** Issue や PR のコメントに `@claude 〜を直して` と書くと、Claude Code GitHub Action が修正して PR を作る（リポジトリ所有者のコメントのみ反応）。必要なシークレット：`ANTHROPIC_API_KEY`
- **公開:** `main` に入るとテスト（`npm test`）を実行し、成功したら Cloudflare に公開する（`.github/workflows/deploy.yml`）。PR でもテストだけ実行する。必要なシークレット：`CLOUDFLARE_API_TOKEN`、`DEPLOY_SIGNING_KEY`（公開版の署名鍵。`npm run deploy-key` で作り、画面に出た秘密鍵を Secrets に入れ、`local/deploy-key.pub` に足された公開鍵をコミットする。無いと公開は止まる。鍵を替えるときは新しい公開鍵を足して古い鍵のまま一度公開し、Mac が新しい公開鍵を受け取ってから Secrets を替える）
- **Mac サービスの更新:** 公開に成功したコミットは `deployed` ブランチに記録される。公開時に Worker へ公開したコミット（`DEPLOYED_SHA`）と、その署名（`DEPLOYED_SIG`。GitHub の Secrets の秘密鍵 `DEPLOY_SIGNING_KEY`（Ed25519）でコミット番号に署名したもの）を持たせ、Mac サービスは処理の確認（5秒ごと）のついでに手元の版と比べて、違えばすぐ早送りで更新して再起動する（`deployed` への記録が遅れている間は30秒おきに再試行。知らせがない場合も10分ごとに確認する）。進む先は、署名が `local/deploy-key.pub` の公開鍵で確かめられ、`deployed` ブランチが指しているコミットだけ（リポジトリや `deployed` ブランチ・Worker に書き込めても、秘密鍵がなければ Mac は更新しない。`local/auto-update.js`）。処理中は終わるまで待つ。ローカルに変更がある・履歴が分岐している場合は更新しない。`package-lock.json` が変わったときは `npm ci --ignore-scripts` を実行し、失敗したら元に戻す。git・npm には時間切れがある。`COURSECUE_AUTO_UPDATE=0` で無効。更新後の再起動は、`npm run install:agent` で登録していれば launchd が行い、`npm start` で動かしているときは自分で新しいプロセスを起こしてから終了する。マージから Mac の切り替わりまでは通常 2〜3 分（GitHub のテスト・公開に約 2 分＋Mac の確認 5 秒以内）。設定の「manabo連携」で Mac サービスの版と公開版の一致を確認できる

## 時間割・出席
- **時間割**（メニュー「時間割」）：週ごとの表に、各回の日付・教室・授業形式（対面／オンライン／オンデマンド／休講）・出席を表示。ホームには「今日の授業」を表示
- **情報の出どころ**（優先順）：自分で設定した値 → CUBICS の授業時間割照会 → 初回・ガイダンス資料から読み取った値 → manabo の「（金曜／2限）」表記・学年暦
- **CUBICS**：同期時に大学の統合ログイン（manabo と同じ）で授業時間割照会を開き、今週〜3週先の週表から曜日・時限・教室と、休講・補講・授業変更の印を読む。時間割の表だけを読み、学生情報欄は読まない。略称の授業名（「コーポ・ファイⅡ」など）は名前の部分一致、決まらなければ曜日・時限で授業に対応づける。読んだ表は Mac の `tmp/coursecue/cubics-grid.html` に保存（読み取りの確認用）
- **ガイダンス資料の読み取り**：同期時に、第1回までの資料（Mac に保存した PDF などの本文）と manabo の授業ページのシラバス・お知らせから教室・授業形式・欠席の上限・出席の取り方・遅刻の扱いを、課題生成と同じ手段（Codex → Claude Code → Claude API）で読み取る。資料の本文に引用が実在する項目だけを使い、資料が変わったときだけ読み直す
- **回ごとの授業形式**：manabo のディレクトリ名やシラバスの授業計画で【動画】（動画配信・オンデマンド）とある回はオンデマンドにする。あわせて授業ページのシラバス（授業計画）・お知らせ・資料に回ごとの形式が書かれていれば反映する（引用が本文に実在し、引用に回番号と形式の言い方があるものだけ）。読んだシラバス・お知らせは Mac の `tmp/coursecue/syllabus/` に保存する（学生名などヘッダーの情報は読まない）
- **授業形式の既定**：回ごとの形式は 自分の記録 → CUBICS の休講 → 資料・シラバスの回ごとの記載 → 授業の既定、授業の既定は 自分で設定した値 → 資料・シラバス → CUBICS からの推定、の順で決める。CUBICS で教室が割り当てられている授業は「対面」、読み取った週のどこにも枠がない授業は「オンデマンド」と推定し、「（CUBICSから推定）」と表示する。違う場合は授業の設定で変更できる
- **お知らせの読み取り**：授業ページのお知らせを 1 件ずつ読み（`local/notices.js`）、見出しの「【第03回，10/09】」から回と日付（学年暦の学期の年。秋学期の 1〜3 月は翌年）、本文から Zoom のリンクとパスコード・教室・休講を取り出す（`state.notices[授業名]`）。休講は時間割と授業開始の同期に反映し（`state.noticeEvents`。CUBICS の休講と同じ扱い）、Zoom・教室・その回の資料はホームの「今日の授業」に出す。前回の同期になかったお知らせは「新しいお知らせ n 件」としてホームに出し、「確認した」（クラウドの仕事 `seen`）で見た印（`state.noticeSeen`）に加えて消す。授業を初めて読んだときは新着にしない
- **同期のまとめ**：同期ごとに「授業 n 件・資料 m 件保存・お知らせ k 件・失敗 j 件」を残し（`state.syncSummary`、授業ごとは `state.courseSummary`）、ホームの「前回の同期」と授業ページの「… に確認」に出す。資料・お知らせ・シラバスの保存や読み取りの失敗は握りつぶさず、要対応に授業名つきで出す
- **OS の通知**：授業開始の同期で資料を保存したときと、出席コードの入力が出たときに OS の通知を出す（アプリは Electron の通知。Windows は AppUserModelID を設定。Mac のコマンドライン版は通知センター。`platform.notify`）
- **資料の回**：保存した資料に回（`round`。ディレクトリの回、お知らせの見出し、なければ名前の「第N回」）を記録し、授業ページの資料欄は回ごとにまとめる
- **授業の開始時刻の同期**：授業の開始時刻（中京大学の授業時間。名古屋 1限 9:00・2限 10:45・3限 13:10・4限 14:55・5限 16:40、豊田 1限 9:30・2限 11:10・3限 13:30・4限 15:10・5限 16:50。キャンパスは「設定 → 自動処理」で選ぶ。既定は名古屋）を過ぎたら、その授業だけを同期する（`local/schedule.js`。開始から 2 時間まで。同じ日に同じ授業は一度だけ `state.classSynced`。曜日・時限が分からない授業と CUBICS で休講の回は対象外）。出席コードの入力が出れば上記のとおり画面に出す。「設定 → 自動処理」で止められる
- **出席**（メニュー「出席」）：授業ごとに出席・遅刻・欠席・公欠・未記録（過去の回で記録なし）・欠席の上限と残りを表示。休講の回は数えない
- **manabo の 2 段階認証**：ログインのあとメールの認証コードを求められたら（月 1 回程度）、PC は入力欄を見つけて（名前・ラベルに code／otp／認証 など、または本文に「認証コード」）`state.mfa` に残し、OS の通知と Web Push で知らせ、SaBoRo の画面（ホームの案内と自動のポップアップ）で入れたコードをクラウド経由で受け取る（`POST /api/mfa` で置き、PC が `POST /api/agent/mfa` で 1 回だけ取り出す。`mfa_codes`。15 分で無効）。受け取ったら「30 日間はこの確認を表示しない」などのチェックを入れてから送り、ログインからの処理を続ける（`local/manabo.js` の `finishLogin`。コードが違えば 3 回まで入れ直せる。10 分待っても届かなければその同期は失敗にして次回また求める）
- **出席確認**（授業ページの「出席確認」）：PC が授業ページを開き、出席コードの入力（manabo の prompt）が出ているかだけを確かめる（クラウドの仕事 `attcheck`。課題・資料は読まない）。出ていれば同期のときと同じく入力の画面を出し、出ていなければ「現在、出席は受け付けておりません」と出す（結果は授業の情報に残す。`state.attendanceCheck`）。入力の画面には、同じ授業（manabo の授業 ID）の他の利用者がその日に入れたコードを「他ユーザーの入力コード」として出す（PC が manabo に入れたコードをクラウドの `attendance_codes` に 1 人 1 授業 1 日 1 件で残し、`/api/attendance-codes` で自分以外の分を件数つきで返す。押すと入力欄に入る）
- **この端末への通知**（設定の「この端末への通知」。Web Push）：「この端末で通知を受け取る」で Service Worker（`dist/sw.js`）を登録し、クラウドの VAPID の公開鍵（`GET /api/push/key`。鍵は最初に使うとき 1 度だけ作って D1 の `push_keys` に置く）で購読して `POST /api/push/subscribe` に登録する（端末ごと。`push_subscriptions`）。iPhone は「ホーム画面に追加」した saboro からだけ設定できる（iOS 16.4 以降）。送るのはクラウド（`server/push.js`。RFC 8291 の aes128gcm と VAPID を WebCrypto で実装）：PC が状態を保存するたびに前の状態と比べて「出席コードの入力が出た」「新しいお知らせ」を送り、毎朝 9:05 の定期処理で 24 時間以内に締切の未提出の課題を送る。消えた購読（404・410）は消す。「テスト通知を送る」（`POST /api/push/test`）で届くか確かめられる。接続を解除すると購読も解除する

## 運用

- 料金の条件：月額（2,500 円。`server/billing.js` の `MONTHLY_YEN`。管理画面で入れていなければこれを出す）・月額に含む課題生成の回数（60 回）・超過分の倍率（1.5 倍）・請求の為替（1 ドル＝150 円）は、特定商取引法に基づく表記と同じ固定値（`server/ai.js` の `TERMS`）。変えるときは `site/public/tokushoho.html` と同時に変える（`tests/site.test.js` で照らす）。管理画面の為替は利益の計算だけに使う。回答を作成できなかった回（途切れた・拒否された）は回数に数えず請求もしない
- Stripe の Webhook で選ぶ通知：`invoice.paid`・`checkout.session.completed`・`checkout.session.async_payment_succeeded`・`charge.refunded`・`customer.subscription.created/updated/deleted`・`charge.dispute.created`・`charge.dispute.closed`（チャージバック。未割り当てに入るので管理画面で割り当てる）
- Workers のログ（`wrangler.jsonc` の `observability`）を保存しており、API の失敗（`request_failed`）は経路と原因が残る（鍵・本文は出さない）
- 障害の通知：毎日 9:05（日本時間）の定期実行で、直近 3 日に PC が接続した利用者のうち 24 時間以内に失敗した人・2 日以上同期していない人が多ければ（3 人以上かつ 3 割以上）、または定期処理で失敗があれば、GitHub の Secrets の `ALERT_WEBHOOK_URL`（Slack・Discord などの Webhook）に送る（`server/worker.js` の `alertOperator`）
- D1 の変更：新しい表は `server/schema.sql`、既にある表の変更は `migrations/` の番号つきの SQL（`migrations/README.md`）。公開の前に D1 の時点（Time Travel の bookmark）をログに残す
- Worker を前の版に戻す：`npx wrangler deployments list` で版を確かめ、`npx wrangler rollback <版の ID>`。D1 を戻すときは Actions のログの bookmark で `npx wrangler d1 time-travel restore coursecue-private --bookmark=<bookmark>`
- デスクトップ版の配布：`package.json` の版を上げてからタグ `desktop-v<版>` を付ける。テストが通ってから作り、タグと版が違う・その版が公開済みのときは止まる。配布用リポジトリに書き込むトークン（`SABORO_RELEASE_TOKEN`）は `gh` を使うステップだけに渡し、取り込む `@napi-rs` のパッケージは `package-lock.json` の integrity と照らす
