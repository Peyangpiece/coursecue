# saboro

授業・課題・提出状況・本人対応タスクを管理するアプリ。

未接続でも授業・課題・締切・下書き・提出済み記録を利用できる。データはブラウザ内に保存し、設定からJSONバックアップを出力・読込できる。ブラウザの保存データを削除すると消えるため、バックアップを利用する。

manabo自動連携は現状、登録済みMacと接続キーを使用する個人用構成。複数利用者向けのアカウント・クラウド同期・自動連携の分離は未実装。

## 構成
- 公開UI: Cloudflare Workers / Firebase Hosting
- 認証付き同期API・処理キュー: Cloudflare Worker + D1
- Macエージェント: `local/bridge.js`（15秒ごとにキュー確認、毎日16:30に同期）
- manabo操作: Playwrightの専用ブラウザ。大学の正規のログインフォームを利用
- 課題生成: 資料テキストを根拠に構造化出力で生成。Codex CLI → Claude Code（`claude -p`）→ Claude API（`claude-sonnet-5-5`）の順に試し、未インストール・未ログイン・利用枠超過・形式不正などで失敗したら次へ進む。使った手段は課題詳細の「生成」に表示
  - Claude APIを使う場合は `npm run setup:claude-api` でAPIキーをキーチェーンに保存し（入力は * で表示。`pbpaste | npm run setup:claude-api` でクリップボードからも可）、Macサービスを再起動
  - CLIの場所は自動で探す。見つからない場合は `COURSECUE_CODEX` / `COURSECUE_CLAUDE` で指定。モデルは `COURSECUE_CLAUDE_MODEL`（Claude Code）/ `COURSECUE_CLAUDE_API_MODEL`（Claude API）で変更可
- 認証情報・接続キー: macOSキーチェーン。平文パスワードはクラウドへ送信しない。公開設定はRSA-OAEP + AES-GCMで暗号化し、登録Macだけが復号する

## セットアップ
1. `npm ci` / `npx playwright install chromium`
2. `npm run setup`（Keychainバイナリのコンパイル・APIキーの設定）
3. `npm run seed`（既存課題・資料の記録をローカルへ取り込む）
4. `npm start` または `npm run install:agent`
5. http://127.0.0.1:8766/setup で本人がmanaboのIDとパスワードを入力
6. 「saboroを接続」でこのブラウザを接続（接続キーはURLフラグメントから読み、直ちに削除）
7. 設定画面で授業日を確認。日付が分からない回は走査しない

## 実装範囲・提出制御
- 新しい課題の検出は実行日の前後7日の授業回が対象。授業タイトルの日付、設定済み日程、または大学の学年暦（`dist/academic-calendar.json`、2026秋学期）を使う。学年暦は授業ページの「（金曜／2限）」表記から曜日を読み、祝日・休講日を除いた第1〜15回の日付を未設定の回に入れる
- **資料の自動ダウンロード**：同期のとき、まだダウンロードしていない資料だけを授業ごとのフォルダ（なければ作成）に保存する。保存先は画面の「設定 → 自動処理 → 資料のダウンロード先」の「フォルダを選択…」で、Mac に出る「フォルダを選択」画面から選ぶ（ホームフォルダ内のみ。「既定に戻す」で `2026秋学期` フォルダ）。そのフォルダで初めての同期のときだけ、対象期間外の回も含めて全回の資料を確かめる。自分で消した資料はダウンロードし直さない
- **資料を開く**：授業ページの「資料」で資料名を押すと、Mac に保存したファイルを Mac の既定のアプリで開く（Mac サービスの `http://127.0.0.1:8766/open?id=<sha256>` 経由。記録済みでダウンロード先の中にあるファイルだけ）。Mac 以外の端末ではローカルサーバーに届かないため、manabo 上のファイルを開くリンクを主にし、「Mac」は補助にする
- **同期の速さ**：全授業を回って提出状況・資料を集め、保存して画面に反映してから回答を生成する。同期中は画像・フォント・動画を読み込まない。未提出課題の提出確認は授業ページを開いたついでに行う。クラウドへの送信は授業ごとにまとめる。ホームに前回の同期にかかった時間（CUBICS・授業・回答生成の内訳）を表示する
- 登録済みで未提出の課題は、対象期間や授業日の設定に関係なく毎回の同期で提出状況を確認する
- 一覧の提出済みチェックは提出済み。下書きと提出済みを区別
- 新規課題は資料から生成。根拠引用が資料と一致しない場合は自動提出しない
- 本人の経験が足りない場合は要対応。補足入力後に生成できる
- クイズは「回答開始」から設問ページへ進み、資料を根拠に自動入力する。回答入力後は専用ブラウザを保持して停止し、本人がmanaboの提出ボタンを押す。自動提出・アプリからの代理提出は行わない。
- 出席コードがある場合は問題だけ回答し、ブラウザをそのまま残して待機。同期も一時停止
- 通常レポートは自動生成まで。アプリの「提出」を本人が押した場合だけ送信
- 試験形式は対象にしない（クイズ形式のみ自動提出）
- 送信直前に意図をローカル記録し、結果不明は再送しない
- 追加認証・未知のフォーム・単独で特定できない提出ボタンは本人対応
- 実データは接続キー必須のAPI内だけに保存。未認証で参照できない
- Macが起動・ログイン中のみ動作。クライアントだけではmanaboを操作しない

## 検証
`npm test`。実際の大学サイトに送信しないネットワーク模擬フォームで、提出完了・重複防止・出席コード待機を確認。
Codex生成は短い検証問題で実行確認済み。実際のmanaboのログイン・課題提出は、本人の認証情報入力後に検証が必要。

## 公開
公開先は Cloudflare（https://coursecue.hrk-6888.workers.dev ）。`main` に入ると自動で公開される。
旧URL（https://coursecue-2026.web.app ）は Cloudflare へ転送するだけにしてある（`firebase.json`）。転送設定を変えたときだけ `npm run deploy:firebase` を手動で実行する。実データ同期はCloudflare D1を使用。

認証付きバックエンドを公開済み。Macサービスが同期・自動ログイン・下書き生成・提出を実行する。初回はMac設定画面で認証情報を保存し、saboroを接続する。

## 自動修正・自動公開（GitHub）
- **修正:** Issue や PR のコメントに `@claude 〜を直して` と書くと、Claude Code GitHub Action が修正して PR を作る（リポジトリ所有者のコメントのみ反応）。必要なシークレット：`ANTHROPIC_API_KEY`
- **公開:** `main` に入るとテスト（`npm test`）を実行し、成功したら Cloudflare に公開する（`.github/workflows/deploy.yml`）。PR でもテストだけ実行する。必要なシークレット：`CLOUDFLARE_API_TOKEN`
- **Mac サービスの更新:** 公開に成功したコミットは `deployed` ブランチに記録される。公開時に Worker へ公開したコミット（`DEPLOYED_SHA`）を持たせ、Mac サービスは処理の確認（5秒ごと）のついでに手元の版と比べて、違えばすぐ早送りで更新して再起動する（`deployed` への記録が遅れている間は30秒おきに再試行。知らせがない場合も10分ごとに確認する）。処理中は終わるまで待つ。ローカルに変更がある・履歴が分岐している場合は更新しない。`package-lock.json` が変わったときは `npm ci` を実行し、失敗したら元に戻す。`COURSECUE_AUTO_UPDATE=0` で無効

## 時間割・出席
- **時間割**（メニュー「時間割」）：週ごとの表に、各回の日付・教室・授業形式（対面／オンライン／オンデマンド／休講）・出席を表示。ホームには「今日の授業」を表示
- **情報の出どころ**（優先順）：自分で設定した値 → CUBICS の授業時間割照会 → 初回・ガイダンス資料から読み取った値 → manabo の「（金曜／2限）」表記・学年暦
- **CUBICS**：同期時に大学の統合ログイン（manabo と同じ）で授業時間割照会を開き、今週〜3週先の週表から曜日・時限・教室と、休講・補講・授業変更の印を読む。時間割の表だけを読み、学生情報欄は読まない。略称の授業名（「コーポ・ファイⅡ」など）は名前の部分一致、決まらなければ曜日・時限で授業に対応づける。読んだ表は Mac の `tmp/coursecue/cubics-grid.html` に保存（読み取りの確認用）
- **ガイダンス資料の読み取り**：同期時に、第1回までの資料（Mac に保存した PDF などの本文）と manabo の授業ページのシラバス・お知らせから教室・授業形式・欠席の上限・出席の取り方・遅刻の扱いを、課題生成と同じ手段（Codex → Claude Code → Claude API）で読み取る。資料の本文に引用が実在する項目だけを使い、資料が変わったときだけ読み直す
- **回ごとの授業形式**：manabo のディレクトリ名やシラバスの授業計画で【動画】（動画配信・オンデマンド）とある回はオンデマンドにする。あわせて授業ページのシラバス（授業計画）・お知らせ・資料に回ごとの形式が書かれていれば反映する（引用が本文に実在し、引用に回番号と形式の言い方があるものだけ）。読んだシラバス・お知らせは Mac の `tmp/coursecue/syllabus/` に保存する（学生名などヘッダーの情報は読まない）
- **授業形式の既定**：回ごとの形式は 自分の記録 → CUBICS の休講 → 資料・シラバスの回ごとの記載 → 授業の既定、授業の既定は 自分で設定した値 → 資料・シラバス → CUBICS からの推定、の順で決める。CUBICS で教室が割り当てられている授業は「対面」、読み取った週のどこにも枠がない授業は「オンデマンド」と推定し、「（CUBICSから推定）」と表示する。違う場合は授業の設定で変更できる
- **出席**（メニュー「出席」）：授業ごとに出席・遅刻・欠席・公欠・未記録（過去の回で記録なし）・欠席の上限と残りを表示。休講の回は数えない
